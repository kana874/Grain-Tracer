# GrainTracer v0.9.0-alpha — A/B中心ワークスペース（P1〜P6実装）

対象: `validation` ブランチ。更新日: 2026-10-14。
画像解析アルゴリズム: `boundary-v18-reflected-edge-v1`（v0.8.1から変更なし）。
プロジェクト形式: v4（既存ファイル・評価履歴を保持）。

## P1：A/B比較のズーム・パン

- 各候補画像上でホイール操作すると、カーソル位置を中心に25〜800%でズーム。倍率はA/B同期し、現在の倍率を表示する。
- 中ボタンドラッグは評価描画を開始せず視野のみ移動。A/Bは同期してスクロールする。
- 左ドラッグは選択候補に沿う一筆評価、左クリックは短区間の正例・負例、検出漏れは2点指定を維持。
- UI上の画像画素座標はDOMサイズ・倍率・スクロールから変換し、プロジェクトにはプレビュー元座標として保存。

## P2：ROI限定の高速A/B比較

- 初回は`ensureFeatures()`で全体の特徴量を計算し、プレビュー画像の既存キャッシュを使う。
- 比較候補は128/256/512pxのROIと周囲64pxのハロー（画像外ではクリップ）だけを切り出して、`src/local-ab-engine.js`で評価する。生成結果は選択ROIだけを元座標へ戻す。
- プレビュー全体のA/Bマスク生成は通常行わない。局所較正の全画面座標系を持つ設定は自動で全画面処理にフォールバック。
- `Worker`が使える環境では`local-ab-worker.js`で特徴量のROI部分だけを別スレッド処理する。非対応環境ではメインスレッド処理へフォールバック。
- 候補キャッシュは画像指紋・ROI・判定パラメータ・特徴量設定・ラベル更新世代をキーとするLRU（最大10件）。比較実行時間・キャッシュ命中/失敗数を記録。
- 現行のNeighbor Support / Connected Componentや長距離Hysteresisの関係で、一部特殊形状ではROI処理と全画像処理が異なる可能性がある。合成fixtureで内部ROIと画像端ROIの一致を検証し、実画像の受入時も端部検出/偽線を確認する。

## P3：複数ROIの選好統合

- 単一ROIでBが勝っただけでは全体候補を更新しない。同じA/B条件について、重なりの大きいROIの評価を独立票として数えない。
- 少なくとも2つの独立した領域で勝利数が上回った場合に初めてChampionを更新。
- 重なり合う領域での連打は最新の評価で置換。判断不能と両方不正解も保持。
- 次のROIは既存キャッシュ特徴量から素早くスコア推定。A/B候補の違い、未評価画素、画像端、過去の重複を反映。Validation/Test/未確定ROIと除外領域を選好学習に使用しない。
- 過去のA/B履歴から再開する場合、v0.9では`championAfter`（複数ROIで確認済み）を復元。旧履歴は既存の取り扱いを維持。

## P4：手動補正との統合

- 正解・非粒界・検出漏れ評価は、独立した部分ラベル（Positive/Negative/Unknown）として維持。
- 一筆ストロークは分離した線へ飛ばないようギャップで停止し、1操作でUndo/Redo可能。
- 比較候補は既に評価されたPositiveとNegative画素上のみで、弱い監督信号`manualEvidence`を計算。Unknown画素は負例として利用しない。
- `manualEvidence`はA/B提案器の探索スコアに小さな補正として反映し、A/B選好を上書きしない。
- Validation/Test/仮ROIでの選好学習・手動学習は行わない。

## P5：全体採用と簡素化UI

- 通常表示は「A/B学習ワークスペース」。BMP読込、A/B・手動補正、Validation ROI設定、保存、診断、必要な全体再解析だけを見せる。
- Auto Tune v2 / One-click Optimization / Topology / Gap / Classifier等は削除せず`詳細機能を表示`で復帰。選択状態はlocalStorageで保持。
- A/B自動選好は独立したValidation ROIのTrue Precision/Recall/F1で検証する。F1が0.5ポイント以上改善し、Recall/Precision各2ポイント超の低下がなく、最低12画素の検証線がある場合だけ全体適用。
- Testは探索/候補比較/Guardに使用せず、最終評価専用。検証済みValidation ROIがない場合は自動採用しない。
- 学習状態に最近100回の平均比較時間・キャッシュ命中数・Validation F1の改善/停滞/悪化と採用/保留履歴を表示。

## P6：自動テスト、診断、長時間確認

- `tests/v09-phases.test.js`でズーム中心保存・中ボタンパンの座標、ROIの合成画像で全画面と一致する結果、キャッシュ衝突/追い出し、離れたROI集計、Positive/Negative部分ラベル、Holdout除外、通常UI、120票履歴、100回の実際のROI候補生成を検証。
- 元画像規模の実BMPでの速度・最終F1改善およびEdgeブラウザでのホイール/中ドラッグ100回操作は未測定。添付診断(21)には**従来**のAuto Tune 52.4秒 / 全体特徴量 9.7秒（1800×1320px）が記録されるが、v0.9の実測値ではない。
- テスト結果はGitHub Actions「test」を確認。性能数値を約36倍高速化と断言しない。実運用の診断ZIPの`performance.localAb`とValidation履歴で確認する。

## 推奨操作

1. BMPとプロジェクトを読み込み（必要ならプロジェクト保存）、右パネル「A/B比較・手動補正を開く」。
2. 候補選択を連続実行。ホイールで拡大、中ドラッグでパン。A/B同期。
3. どちらも悪い場合は`自動で次へ`を止め、候補A/Bを選んでドラッグ評価。必要な場合のみ検出漏れを2点で指示。
4. 複数領域で一致したChampionが得られたらValidation ROIを用意し「選択した最良設定を検証して採用」。
5. Validationで改善が確かめられた候補だけ全体に反映される。Testは最後まで未使用。
6. 以前の機能はヘッダー「詳細機能を表示」で使用可能。診断ZIPは標準画面から出力可能。

## 既知の限界

- ROI比較は1800×1320px等の解析プレビュー座標系であり、元BMPの全解像度ではない。
- 選好を繰り返すことは粒界モデルの確実な精度向上を保証せず、未見のValidation/Test ROIによる確認が必要。
- ノードベースの連続処理テストは完了。実画像の長時間ブラウザUI・パフォーマンス・精度評価は次の受入試験項目。
