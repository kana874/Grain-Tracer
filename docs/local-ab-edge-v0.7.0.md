# GrainTracer v0.7.0-alpha：画像端の復元と局所A/B比較

対象：GitHub `validation` ブランチ（mainではない）。作成日：2026-10-14。

## 画像端修正

前版では `edgeFrameGuard:1` に加え、特徴量ごとに5 / 7 / 14 px程度の内部余白を必要とし、Dark重み0の設定では画像端近傍で判断材料がありませんでした。

- `src/edge-padding.js`：プレビューの上下左右を24px反射拡張。feature計算後に元の画素座標へ戻し、外側の偽画素を結果としては出力しません。
- `src/analysis.js`：Ridge/Color/Dendriteなどを余白付き画像で計算、画像端でも特徴利用可能。`edgeFrameGuard=0` がデフォルト。
- `src/app.js`：通常解析・分類器比較で frameGuard 0。Auto Tuneの高速評価・処理済候補評価も0。
- 最外周画素は内部へ連続した境界だけを許可し、外枠に沿う線だけでは最終境界へ残さない。NMS/MinComponentの処理や除外は維持。

注意：反射は境界条件の近似であり、元画像の外側に実際の情報があるわけではありません。実画像での端部Recallと偽の枠線を再検証してください。

## 局所A/B比較の使用方法

1. BMPを読み込み、右側「簡易フィードバック学習」→「局所A/B比較モードを開く」を選択する。
2. 左側の画像をクリックして256pxの評価ROIを移動する。128/256/512px（**プレビュー解像度**）を選べる。画像端まで選択可能。
3. Bの比較条件を選び「この条件で比較」を押す。
   - A = 現在の抽出設定で新規抽出した結果。Gap/Topology事後適用済み表示とは異なる場合がある。
   - B = Aと同一の特徴量・ROI・除外範囲を使用し、感度+8 / -8 / +16 / NMS切替の一つだけを変更。
   - B =「旧・画像端処理」は**例外**。Aの反射パディングと異なり、旧特徴量計算とframeGuard=1を使用する、画像端回復の検証用。
4. 2画面を同時表示し、100/200/400/800%の同期拡大とスクロールで確認する。Aのみ/Bのみの画素数は精度ではなく抽出量の差。
5. Aが良い／Bが良い／両方不正解／判断不能をクリックし、**選好履歴を保存**する。選好はGround Truthや正式なF1には使用しない。
6. AまたはBを手動評価対象として選び、表示された候補の短い区間を「正解」「誤検出」でクリックする。抽出されなかった粒界は「検出漏れ」で2点指定する。
   - 1/3/5/9pxから一回の評価範囲を変更できる。選択は選択ROIの外へ出ない。除外範囲も書き込まない。
   - この操作は既存の部分ラベル（Positive/Negative/Unknown）へ即時追加され、プロジェクト保存とUndo/Redoに対応。
7. ダイアログを閉じて「評価結果を使って再調整」を手動実行し、候補を比較する。**A/Bを選んだだけでは重み変更・自動学習・全体再解析を実行しない。**

## 永続化

Project Format v4を維持し、既存Project v1〜v4を読み込み可能。
- `localAbReviews`：勝者、ROI、Bの変更条件、A/B抽出画素数、感度・NMS・重みなど設定、アプリとアルゴリズム版、日時・画像指紋を保存（500件）。
- `feedbackReviews`：従来の正解・誤検出・検出漏れに加えて、`source=local-ab`、`candidate=a/b`、ROI、Bのvariantを保存（2000件）。
- Diagnostic JSONに`localAbReview`と`feedbackReview`を追加。自動保存は既存のIndexedDBを利用する。

## 現時点の限界と受入れ試験

- A/Bは**解析プレビューの解像度**で実施。元BMPの高解像度切出しではありません。正解データ作成モードと同等の元画素単位を求める場合、元画像ROI読み込みの別拡張が必要です。
- 実画像で改善を保証しません。正しい粒界の端部再現と枠線の誤検出の両方を確認してください。
- A/Bは選好データの収集まで。学習へ自動投入し、2条件のパラメータを勝手に入れ替える方式ではありません。
- 比較・部分ラベルから画像全体のTrue Precision/F1は算出しません。正式な指標は従来どおり人間が全粒界を確認した完全評価ROIで評価します。
- 合成テスト：画像の反射マッピング、端部Ridge復元、外枠ノイズ拒否、ROI境界、選好保存互換、既存の除外/評価Role/Topology回帰。
- 実BMP・元プロジェクトで次を確認：同じ画像の同じROIにおける端部Recall / False Positive / Negative Leakage / Verified ROI Precision/F1 / Open@3。Validation/Testは調整データに混ぜない。
