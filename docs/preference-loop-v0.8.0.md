# GrainTracer v0.8.0-alpha — A/B選好から始める４フェーズ学習

対象: GitHub `validation` ブランチ。既存のProject Format v4のまま互換保存。
2026-10-14。

## 操作フロー

1. BMPを読み込む。「簡易フィードバック学習」から「局所A/B比較モードを開く」。
2. まず「選好からB候補を自動生成」「選択後に次のA/Bを自動生成」をONにしてA/Bを比較。通常は人間が「Aが良い」「Bが良い」「両方不正解」「判断不能」をクリックするだけ。
3. 画面が次の候補を再生成する。前回Bが勝った場合はBが新しいAになり、過去の選好を考慮した新しいBが生成される。
4. 「次のROIも自動推薦」がONなら、新しいA/Bの相違・未評価・端部・既評価回数から次の評価範囲を自動的に移動する。
5. 修正したい範囲がある場合は「選択後に次のA/Bを自動生成」をOFFにして、「Aを修正」または「Bを修正」を選ぶ。「正解」「誤検出」を選んで**候補に沿ってドラッグ**すると、1回の操作でまとめて部分ラベル化する。間違った画素はUndo可。「検出漏れ」は既存の2点指定を使用。
6. 設定を全体へ反映するには「選択した最良設定を検証して採用」を押す。「Validationで改善時だけ自動採用」をONにすると、Bが勝ったときにガード検証を自動実施する。
7. **検証済みValidation ROIがない場合、自動採用は行われない**。現在の抽出設定は変更されず、A/Bとお手本作成だけ継続できる。

## Phase 1: 反復A/B選好探索

- `src/preference-optimizer.js`：17の探索方向から変化を選び、過去の勝敗をUCBに似た探索スコアに反映。探索対象：感度、Dark/Ridge/Color/Dendrite重み、Negative Evidence、Min Component、NMS切替。
- `Bが良い` → 勝者Bを新しい基準Aへ昇格。`Aが良い` → Aを維持。`両方不正解`と`判断不能`では優劣を確定しない。
- クリックした場所のA/Bの優劣は**相対選好**であり、画素の正解ラベルではない。
- 保存された同じBMP指紋・同じ特徴量設定・同じアルゴリズム版の選好履歴から、次回も最良候補を再開できる。Validationで採用されない設定は、比較中の候補としてのみ保持し、全体解析へ無断反映しない。
- 既存の手動条件比較も「選好からB候補を自動生成」OFFで利用できる。
- 探索は統計的優先付け付きのパラメータ探索であり、CNN/Transformer等の再学習ではない。現在の特徴抽出器では表現できない線をA/Bだけで復元できる保証はない。

## Phase 2: 一筆評価

- `src/stroke-review.js`：入力されたストロークに沿って最大2px以内の候補画素を選ぶ。連結した粒界ネットワーク全体へのBFS拡張はしない。
- 1回のドラッグを1件の `feedbackReviews`（`selection: guided-stroke`）と1 Undo履歴へ保存。ROI外と除外マスクは不可。
- 正例・負例は実際に人間が指定した範囲にのみ付与する。未知領域はUnknownのまま。クリック式の1/3/5/9px操作も残す。
- ストロークが意図せず別線に近づくケースを避けるため、拡大して線に沿ってなぞるのが推奨。

## Phase 3: Active ROI

- `src/active-roi.js`：候補間の不一致率、まだラベルのない比率、端部、過去のROI評価による重複ペナルティで推薦順位を付ける。
- **学習用候補からは**Validation/Testおよび未確定の評価ROIを除外。Development以外の画像はA/B選好学習不可。
- 診断目的で画像端を手動選択することも可能。ただしTest/Validationの選好は学習に使用しない。
- 真のActive Learningによる不確実性の較正・学習器の誤差推定までは実装していない。A/B不一致を代理指標に使う推薦方式。

## Phase 4: 厳格なValidation検証と自動採用

- `src/preference-adoption.js`：確認済みの`evaluationRole=validation`の完全評価ROI**だけ**から、旧設定と候補設定のTrue Precision/Recall/F1を同条件で計算。
- 採用条件：Validation F1が0.5ポイント以上上昇、RecallとPrecisionは各2ポイントより大きく下落しない、Validationの正解線が最低12画素。
- ROIがない、Test/Validation画像を開いている、上記閾値を満たさない、推論失敗 → **設定を変更せず棄却**。
- Legacy/Training ROIを検証用に代用しない。Test ROIを候補選択・ガード・自動採用判定に使用しない。
- 採用時は既存設定UI・解析マスク・オーバーレイ・診断値を更新。採用と棄却の詳細を`preferenceAdoptions`監査ログ（最大200件）へ保存。

## 保存・診断

- `localAbReviews`最大500件：勝者、ROI、候補の再現に必要なスカラー設定、探索アーム、画像指紋など。
- `feedbackReviews`最大2000件：正解/誤検出/欠落、A/B元、ROI、一筆/クリック判別。
- `preferenceAdoptions`最大200件：採用/棄却理由、Validation使用、ガード基準、旧/新Precision-Recall-F1。
- `diagnostic.json`にもこれらの最近の履歴を記録。プロジェクトと自動保存はProject Format v4を維持。
- 設定履歴に大きなUint8Arrayマスク・Classifierテンソルを複製しない。

## 受入条件・制約

- ノード系自動テスト：提案器の選択、復帰、ドラッグ範囲/除外、ROI推薦/holdout、Validation採用の受入・棄却、Project v4往復、モジュール構文検査。
- ブラウザでの長時間A/B連続操作、大容量BMPの実測、手動ドラッグのイベント動作、継続学習による実画像F1改善は未確認。
- A/Bはプレビュー解像度であり元BMP原寸での粒界再学習ではない。実際の性能比較ではユーザーのValidation/Test役割分離と精密評価ROIの確認が必要。
